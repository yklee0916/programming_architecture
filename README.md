# 1_spaghetti_code

## 개요

이 브랜치는 스파게티 코드(Spaghetti Code)의 전형적인 예제를 보여줍니다. `LoginActivity.java` 파일은 안드로이드 로그인 기능을 구현하고 있지만, 모든 로직이 하나의 메서드(`onCreate`)에 집중되어 있어 유지보수가 어렵고 테스트가 불가능한 구조입니다.

## 현재 코드 상태

### 파일 구조
- `LoginActivity.java`: 모든 로직이 포함된 단일 파일

### 코드 특징
- **모든 로직이 `onCreate()` 메서드 내부에 집중**
  - UI 구성 (LinearLayout, EditText, Button, TextView 생성 및 설정)
  - 사용자 입력 검증
  - 네트워크 호출
  - 데이터 저장 (SharedPreferences)
  - 화면 전환
  
- **깊은 중첩 구조**
  - `onCreate()` → `setOnClickListener()` → `Thread` → `runOnUiThread()` (4단계 중첩)
  
- **하드코딩된 값들**
  - API URL: `"https://api.example.com/login"`
  - SharedPreferences 키: `"user"`
  - 에러 메시지들이 코드에 직접 하드코딩됨
  
- **리소스 관리 부족**
  - `HttpURLConnection`, `BufferedReader` 등이 명시적으로 닫히지 않음
  - 메모리 누수 가능성
  
- **보안 취약점**
  - JSON 문자열을 직접 생성하여 SQL Injection과 유사한 취약점 존재
  - 비밀번호가 평문으로 전송됨 (HTTPS 사용 가정)
  
- **예외 처리 부족**
  - 모든 예외를 `Exception e`로 포괄적으로 처리
  - 구체적인 에러 정보가 사용자에게 전달되지 않음

## 스파게티 코드의 단점

### 1. 유지보수성 저하
- **문제**: 모든 로직이 한 곳에 집중되어 있어 수정 시 전체 코드를 이해해야 함
- **영향**: 작은 변경도 예상치 못한 부작용을 일으킬 수 있음
- **예시**: 에러 메시지를 변경하려면 코드 중간을 찾아 수정해야 함

### 2. 테스트 불가능
- **문제**: 모든 로직이 Activity에 결합되어 있어 단위 테스트 작성이 불가능
- **영향**: 
  - 검증 로직을 독립적으로 테스트할 수 없음
  - 네트워크 호출을 모킹하기 어려움
  - UI 테스트만 가능하며, 통합 테스트에 의존해야 함

### 3. 코드 재사용 불가
- **문제**: 로직이 특정 Activity에 강하게 결합되어 있음
- **영향**: 
  - 다른 화면에서 로그인 기능을 재사용할 수 없음
  - 검증 로직을 다른 곳에서 사용할 수 없음

### 4. 책임 분리 부족 (Single Responsibility Principle 위반)
- **문제**: 하나의 클래스가 너무 많은 책임을 가짐
  - UI 렌더링
  - 사용자 입력 검증
  - 네트워크 통신
  - 데이터 저장
  - 화면 전환
- **영향**: 각 책임을 독립적으로 수정하거나 개선하기 어려움

### 5. 가독성 저하
- **문제**: 
  - 125줄의 긴 메서드
  - 깊은 중첩 구조 (4단계)
  - 주석 없이 모든 로직이 섞여 있음
- **영향**: 
  - 새로운 개발자가 코드를 이해하는데 시간이 오래 걸림
  - 버그를 찾기 어려움

### 6. 확장성 부족
- **문제**: 새로운 기능 추가 시 기존 코드를 수정해야 함
- **영향**: 
  - 소셜 로그인 추가 시 `onCreate()` 메서드가 더 길어짐
  - 로그인 방식이 다양해질수록 코드가 복잡해짐

### 7. 디버깅 어려움
- **문제**: 
  - 모든 로직이 한 곳에 있어 문제 발생 지점을 찾기 어려움
  - 스택 트레이스가 복잡함
- **영향**: 버그 수정 시간이 오래 걸림

### 8. 협업 어려움
- **문제**: 여러 개발자가 동시에 작업하기 어려움
- **영향**: 
  - Git 충돌 발생 가능성 증가
  - 코드 리뷰가 어려움

### 9. 성능 최적화 어려움
- **문제**: 모든 로직이 메인 스레드와 백그라운드 스레드에 섞여 있음
- **영향**: 
  - 비동기 처리 최적화가 어려움
  - 메모리 관리 최적화가 어려움

### 10. 보안 취약점
- **문제**: 
  - JSON 문자열 직접 생성으로 인한 보안 취약점
  - 예외 처리가 부족하여 보안 정보 노출 가능
- **영향**: 
  - 악의적인 입력에 취약함
  - 사용자 데이터 보호 실패 가능
